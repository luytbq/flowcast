# ADR-0007: The Go version may differ from the reference implementation, but every difference must be recorded

- Status: superseded by ADR-0008
- Date: 2026-09-23

## Context

Throughout the port, the rule was: the Go version produces exactly the same bytes, the
same printed lines and the same exit codes as the Python version, across the whole
conformance suite. That rule is what keeps the port from silently going wrong.

But the product has to go further than the original: read mermaid, draw in four
directions, build tables without lanes as flowcharts. In some places the old behavior is
wrong in product terms, for example a table without lanes being reported as an error.
Keeping the rule absolute means freezing those places too.

Conversely, dropping the rule loses the gate: a port that diverges because of a bug and
a port that diverges on purpose look identical in a diff.

## Decision

The Go version may differ, under three conditions:

1. The difference must be listed in `conformance/diverge.txt`, one line per case or CLI
   transcript, with a reason. The Go tests skip exactly those lines when comparing
   against the Python answers, and skip nothing else.
2. The new behavior must have its own gate: a new case, a golden generated by the Go
   version, and that golden may only change when someone looks at the image and reads
   the diff.
3. The difference must be in the README, in the list of intentional differences,
   written for users rather than for porters.

## Consequences

- The conformance suite diff stays meaningful: a golden that changes without a matching
  line in diverge.txt is a bug.
- The Python version remains the answer for everything else, including later additions
  such as merge, so it still runs in `tools/check.sh` and in CI.
- The cost: every intentional behavior change is three tasks instead of one. That is
  the intent, because changing behavior should cost more than fixing a bug.
- When the Python version is no longer used, `diverge.txt` is the complete list of
  places where the two versions split, which makes it a handover document rather than
  junk.
